    Сайт: реклама, SEO и аналитика¶

    Исследование от 2026-10-23. Технический план для настоящего сайта, а не окончательное решение (см. открытый вопрос о технической платформе сайта).

    Эта страница объясняет, что сайту нужно технически, чтобы реклама хорошо работала, салон находили в Google и мы могли измерять, откуда приходят записи. Как запускать саму рекламу: Реклама.

    Кратко¶

    • Достаточно простого сайта на HTML/CSS/JS. Всё описанное ниже работает в браузере посетителя: без сервера, без базы данных, без фреймворка.
    • Отдельный URL для каждого языка (английский на /, затем /de/, /fr/, /it/), текст — прямо в HTML.
    • Общие CSS и JS; данные о бизнесе из business.yml; скрипт проверки против расхождений между языками.
    • Сначала баннер cookie с согласием, потом тег Google и Meta Pixel.
    • Сообщение о записи из виджета Cal.com передаётся в Google и Meta: это одно событие нужно для отслеживания конверсий, оптимизации рекламы и ремаркетинга.

    Структура (простой HTML, без генератора)¶

    Мы оставляем простой статический сайт и редактируем его с помощью ИИ-агента для программирования. Единственный реальный риск — расхождение: одно и то же содержание есть на нескольких языках, и одну копию меняют, а остальные нет. Эти правила помогают держать всё под контролем:

    Правило Зачем
    Одна страница на язык, как в прототипе: /index.html (английский), /de/index.html, … плюс Impressum (выходные данные сайта) и политика конфиденциальности Всего около 4–8 HTML-файлов
    Общие файлы: один styles.css, один main.js (карта, запись, отслеживание, согласие) Дизайн и логика существуют в одном месте; по языкам отличается только текст
    Текст в HTML, а не переключается через JavaScript Google индексирует каждый язык; реклама ведёт на нужный язык
    Данные о бизнесе (цены, часы, адрес, телефон) берутся из business.yml Одно место для изменений; агент обновляет из него все языковые файлы
    Скрипт проверки (например, make site-check): цены и телефон на всех языках совпадают с business.yml, hreflang на каждой странице, одинаковые разделы в одинаковом порядке Автоматически находит расхождения
    Каждое изменение сразу на всех языках То же правило, что и для этой документации (EN + RU)

    Пересматривать подход (например, переходить на генератор статических сайтов) стоит, только если сайт вырастет до многих страниц (блог, отдельная страница на каждую услугу) или его должен регулярно редактировать человек без ИИ-инструментов.

    Вариант Стоимость Примечание
    Infomaniak (вместе с доменом и почтой) Небольшой тариф хостинга, несколько CHF в месяц [проверить] Данные в Швейцарии: проще всего для политики конфиденциальности

    Языки и URL¶

    • Отдельный URL для каждого языка: salonname.ch/ (английский, по умолчанию), /de/, /fr/, /it/.
      • Реклама: немецкое объявление должно вести на немецкую страницу. В поиске Google язык посадочной страницы теперь стал сигналом для подбора (см. Реклама).
      • SEO: Google индексирует каждый язык отдельно, только если у него свой URL.
      • Пересылка: ссылка, отправленная в WhatsApp, открывается на нужном языке.
      • Аналитика: посещения и записи по языкам видны сразу.
    • <html lang="de"> (или en …) на каждой странице.
    • Теги hreflang на каждой странице со ссылками на все языковые версии плюс x-default.
    • / — английская страница, она же x-default (для всех остальных языков).
      • Если язык браузера DE, FR или IT, небольшое окно спрашивает на этом языке, переключиться ли («Möchten Sie diese Seite auf Deutsch sehen?»). При других языках браузера окна нет.
      • Ответ запоминается, и окно больше не появляется. Никакого автоматического перенаправления: Google всегда видит английскую страницу.
      • Баннер cookie появляется после закрытия окна.
    • Выбор языка (небольшой выпадающий список в шапке) ведёт на ту же страницу на другом языке, а не на главную.
    • Текущий раздел сохраняется: при прокрутке адрес следует за разделом (#prices, #faq …), поэтому смена языка открывает тот же раздел.
    • Прототип уже использует эту структуру (с 2026-10-24).

    Язык календаря записи (Cal.com)¶

    • По умолчанию Cal.com показывает страницу записи на языке браузера посетителя. Выбрать язык с сайта мы не можем.
    • Возможный обходной путь (пока не решено, обсудить с партнёрами): одна услуга (event type) на каждый язык, у каждой задан «Interface Language» (настройки услуги; поле API — interfaceLanguage) [проверить в нашем аккаунте Cal.com]:
    Страница Услуга в Cal.com (пример) Interface Language
    / anti-cellulite English
    /de/ anti-cellulite-de Deutsch
    /fr/ anti-cellulite-fr Français
    /it/ anti-cellulite-it Italiano
    • Сначала создать английскую, затем Duplicate для остальных языков и поменять slug, название, описание и Interface Language.
    • Все принадлежат одному человеку, поэтому у них один общий календарь: запись в одной блокирует это время во всех [проверить] тестовой записью.
    • Наши тексты (название, описание, вопросы при записи) пишутся на языке услуги.
    • Держать их одинаковыми: длительность, цена, доступное время и вопросы при записи должны совпадать во всех четырёх. Меняем одну → меняем все.
    • Тогда на сайте у каждой страницы будет своя услуга в data-booking-cal (из business.yml). Сейчас все страницы используют одну услугу.
    • Cal.com загружается только при первом нажатии «Записаться», поэтому посетители, которые не записываются, не отправляют запросов на cal.com.

    Основы SEO¶

    На каждой странице

    • Уникальные <title> и meta description на каждом языке, с местом и услугой: «Anti-Cellulite-Massage in Saanen | Salonname».
    • Один <h1>, понятные заголовки, адрес и телефон текстом (не только на картинке или карте).
    • Канонический URL (каждая языковая версия указывает на саму себя).
    • Теги Open Graph (заголовок, описание, изображение): превью, когда ссылкой делятся в WhatsApp, Instagram, Facebook.
    • Alt-тексты у изображений на языке страницы.

    Структурированные данные (schema.org)

    • Блок JSON-LD HealthAndBeautyBusiness или DaySpa, генерируется из business.yml: название, адрес, координаты, телефон, часы работы, цены, URL, ссылка на запись, изображения, sameAs (Instagram, Facebook, Google Business Profile).
    • Проверить в Google Rich Results Test.

    Файлы и инструменты

    • sitemap.xml со всеми языковыми версиями (и hreflang), robots.txt.
    • Google Search Console и Bing Webmaster Tools: отправить sitemap, следить за индексацией и поисковыми запросами. Bing также влияет на ответы ChatGPT/Copilot.
    • Одинаковые название, адрес и телефон в Google Business Profile и во всех карточках компании (см. Присутствие в локальном поиске).

    Скорость (это ещё и фактор рекламы: медленная посадочная страница делает клик дороже)

    • Изображения в WebP/AVIF, нужного размера, loading="lazy" ниже первого экрана.
    • Шрифты на нашем сервере, а не загружаются из Google Fonts (быстрее, и данные не уходят в Google без согласия).
    • Минимум JavaScript; виджет записи, карту и теги загружать только когда нужно.
    • Проверить в PageSpeed Insights (Core Web Vitals) на телефоне.

    Аналитика и отслеживание¶

    Что используем¶

    Инструмент Зачем Cookie / согласие
    Тег Google (отслеживание конверсий Google Ads) Стоимость записи из рекламы Google, ремаркетинг Да, после согласия
    Meta Pixel Стоимость записи из рекламы Meta, ремаркетинг Да, после согласия
    Статистика сайта: GA4 или инструмент без cookie (например, Plausible, Matomo, Cloudflare Web Analytics) [сравнить] Посещения, страницы, языки, каналы GA4: после согласия. Инструменты без cookie: часто без баннера [проверить]
    Google Search Console, Bing Webmaster Tools Поисковые запросы, индексация Нет (ничего не стоит на сайте)

    GA4 бесплатен, но требует согласия и поэтому не видит отказавшихся посетителей. Инструмент без cookie считает все посещения, но не передаёт данные в Google Ads. Возможная комбинация: инструмент без cookie для статистики плюс тег Google и Meta Pixel только для рекламы.

    Какие события отслеживать¶

    Событие Когда Зачем
    page_view Каждая страница Посещения по языкам и каналам
    book_click Клик по кнопке «Записаться» Интерес; сравнить с записями
    booking_completed Cal.com сообщает об успешной записи Главное событие: стоимость записи, оптимизация рекламы, ремаркетинг
    whatsapp_click, phone_click, email_click Клик по контактной ссылке Записи мимо Cal.com
    directions_click (с app: google / apple / waze / android-chooser), copy_location Кнопки «Как добраться» и «Скопировать адрес» Местный интерес
    voucher_click Клик по ссылке на сертификат Интерес к сертификатам

    Передача записи из Cal.com¶

    Окно Cal.com — это iframe с другого домена, поэтому наш тег не видит, что происходит внутри. Виджет отправляет нашей странице события JavaScript, и мы передаём их дальше:

    Cal.ns["anti-cellulite"]("on", {
  action: "bookingSuccessfulV2",   // [verify] event name in the Cal.com embed docs
  callback: (e) => {
    gtag("event", "booking_completed", { method: "cal.com" }); // Google
    fbq("track", "Schedule");                                  // Meta standard event
  }
});
    • Люди, которые записываются по прямой ссылке (описание профиля Instagram, Google Business Profile), не заходят на наш сайт. У Cal.com есть свои интеграции (Google Analytics, Google Tag Manager, Meta Pixel) для его страниц записи [проверить], на каких тарифах они доступны.

    UTM-метки¶

    Каждая ссылка, которую мы размещаем (реклама, описание профиля Instagram, Google Business Profile, QR-коды, партнёры), получает UTM-метки. Допустимые значения и реестр всех ссылок — на отдельной странице: UTM-ссылки.

    Пример: https://salonname.ch/?utm_source=flyer&utm_medium=print&utm_campaign=opening-2026&utm_content=a6-station

    Для чтения меток код не нужен: GA4, Plausible, Matomo и рекламные платформы сами читают UTM-метки из адреса первой страницы и запоминают источник на весь визит. Задача сайта — не потерять их и передать в запись.

    1. Не терять параметры

    • Перенаправления сохраняют параметры: http → https, www → без www.
    • Никаких UTM-меток на внутренних ссылках (меню, переключатель языка, кнопки): они начинают новый визит с неправильным источником.
    • Canonical без параметров: <link rel="canonical" href="https://salonname.ch/de/">, чтобы Google не индексировал копии страницы с ?utm_….

    2. Передать источник в запись

    Запись происходит в iframe Cal.com, поэтому мы сами связываем booking_completed с источником:

    // main.js: remember the campaign info of this visit (first page)
const p = new URLSearchParams(location.search);
const keys = ["utm_source","utm_medium","utm_campaign","utm_content","utm_term","gclid","fbclid"];
const utm = Object.fromEntries(keys.filter(k => p.get(k)).map(k => [k, p.get(k)]));
try { if (Object.keys(utm).length) sessionStorage.setItem("utm", JSON.stringify(utm)); } catch (_) {}
const saved = (() => { try { return JSON.parse(sessionStorage.getItem("utm") || "{}"); } catch (_) { return {}; } })();

// a) send the source with the booking event
Cal.ns["anti-cellulite"]("on", {
  action: "bookingSuccessfulV2",          // [verify] event name
  callback: () => gtag("event", "booking_completed", { ...saved })
});

// b) store the source with the booking in Cal.com (booking data, webhooks)
//    Cal.com accepts metadata as query parameters: metadata[key]=value  [verify]
const meta = Object.entries(saved).map(([k, v]) => `metadata[${k}]=${encodeURIComponent(v)}`).join("&");
document.querySelectorAll(".js-book").forEach(b =>
  b.dataset.calLink = `salon/anti-cellulite${meta ? "?" + meta : ""}`);
    • a) даёт записи по источникам в GA4/Plausible и Google Ads.
    • b) сохраняет источник в самой записи в Cal.com, даже если посетитель отказался от cookie [проверить]. Пригодится позже, например: «какой канал приводит клиентов, которые покупают абонементы».
    • В sessionStorage хранятся только метки кампании, без персональных данных, и они удаляются при закрытии вкладки. Указать это в политике конфиденциальности [проверить].

    3. Анализ

    Где Что видно
    GA4 → Отчёты → Привлечение → Привлечение трафика Визиты по source/medium/campaign; с ключевым событием booking_completed — записи по источникам
    GA4 → Исследования Свои таблицы, например кампания × языковая страница × записи
    GA4 → Администратор → Группы каналов Свой канал «Print» для utm_medium=print (GA4 его не знает)
    Plausible / Matomo Источники с фильтрами по UTM; цели для записей
    Google Ads / Meta Ads Manager Стоимость и записи по кампаниям и объявлениям
    Записи и данные вебхуков Cal.com Источник, сохранённый в каждой записи (пункт 2b), можно выгрузить в таблицу

    Каждый месяц: по каждому каналу затраты ÷ записи = стоимость записи, сравнить с лимитом в закрытых заметках.

    Ремаркетинг: как это работает¶

    Visitor opens salonname.ch/de/
  → Google tag / Meta Pixel load (only after cookie consent)
  → Google/Meta recognise the person (cookie + logged-in Google/Instagram account)
  → they add the person to OUR list "website visitors"

Visitor completes a booking in the Cal.com window
  → our page catches the Cal.com booking event
  → we send "booking_completed" to Google/Meta
  → they add the person to the list "booked"

In Google Ads / Meta Ads Manager:
  audience = "website visitors (last 30 days)" MINUS "booked"

    Схема по-русски: посетитель открывает сайт → после согласия на cookie загружаются тег Google и Meta Pixel → Google/Meta узнают человека и добавляют его в наш список «посетители сайта». Если человек записался, сайт отправляет booking_completed, и он попадает в список «записались». В рекламном кабинете аудитория = «посетители за 30 дней» минус «записались».

    • Мы никогда не видим, кто в списках, только их размер.
    Платформа Минимальный размер списка для показа рекламы Сколько человек остаётся в списке
    Google (КМС / Demand Gen / YouTube) около 100 активных пользователей за последние 30 дней [проверить] до 540 дней
    Поиск Google около 1000 [проверить] —
    Meta около 100 человек [проверить] до 180 дней
    • Потери: отказ от cookie, защита приватности в Safari/iPhone, блокировщики рекламы. В списки попадает, возможно, 40–60% посетителей [проверить].
    • Ставить теги с первого дня: списки наполняются только с момента, когда тег заработал.
    • Позже (по желанию): Conversions API от Meta и расширенные конверсии Google: запись передаётся ещё и с сервера (вебхук Cal.com → бессерверная функция), поэтому теряется меньше записей. Потребует обновления политики конфиденциальности.

    Согласие на cookie¶

    • Рекламные теги (тег Google, Meta Pixel) ставят рекламные cookie. Google требует согласия на персонализированную рекламу от пользователей из ЕЭЗ, Великобритании и Швейцарии [проверить], а многие наши клиенты — туристы из ЕС.
    • Баннер cookie с настоящим выбором: «Принять» и «Отклонить» одинаково заметны; категории (необходимые / статистика / маркетинг). Библиотеки с открытым кодом, например CookieConsent (orestbida) или Klaro [сравнить].
    • Google Consent Mode v2: всё начинается в состоянии «отклонено»; теги работают полностью только после «Принять». Meta Pixel загружается только после согласия.
    • Без согласия посетитель не отслеживается и не попадает ни в какие списки. Это нормально: мы теряем часть данных.
    • Сам баннер — на всех языках сайта.
    • В политике конфиденциальности указан каждый инструмент (Google Ads, Meta Pixel, инструмент статистики, Cal.com, тайлы карты, хостинг). См. Право — сайт и реклама.
    • Карта: прототип загружает тайлы OpenStreetMap напрямую. При этом IP-адрес посетителя уходит на сервер тайлов: это указано в шаблоне политики конфиденциальности; как вариант — загружать карту только после клика [проверить].
